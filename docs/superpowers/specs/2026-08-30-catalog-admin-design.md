# 实验目录与管理员范式工作台设计

日期：2026-08-30  
状态：已批准并实现

## 1. 目标

在保留“知觉之间”现有视觉风格、配色和名称的前提下，调整平台的信息架构，并为教材编写人员提供一个适合 GitHub Pages 静态托管阶段的范式维护工作台。

平台面向认知心理学学习者，定位为行为实验范式的教学体验网站。它不保存学习者数据，也不得被描述为正式科研数据采集平台。

## 2. 页面结构

### 2.1 首页

- 保留现有品牌、视觉风格、精选范式和核心介绍。
- 顶部“实验目录”链接跳转到独立的实验目录页面。
- 删除面向普通学习者的“扩展范式库”板块及上传说明。
- 扩充首页底部为“使用须知”，明确：
  - 网站仅供教学和自我体验；
  - 不保存任何实验数据；
  - 页面关闭或刷新后数据可能丢失；
  - 学习者应在离开前导出本次结果；
  - 网站不适用于正式科研实验或真实被试数据采集。

### 2.2 实验目录页

- 使用独立页面 `experiments.html` 展示全部已发布范式。
- 提供关键词搜索、认知领域筛选和任务类型筛选。
- 筛选结果即时更新，并提供空结果状态和清除筛选操作。
- 每张范式卡片展示名称、简短简介、分类、预计时长和主要指标。
- 点击范式卡片进入该范式的说明页，不直接启动实验。

### 2.3 范式说明页

- 由平台统一渲染范式包中的 `description.md`。
- 页面展示范式名称、分类、预计时长、说明正文和“开始实验”按钮。
- 页面顶部和正文底部均可提供“开始实验”按钮。
- 不强制学习者阅读完成，不记录阅读状态；熟悉范式的学习者可以直接开始。
- Markdown 仅允许安全的标题、段落、列表、表格、引用、链接和图片。脚本、事件属性和危险 HTML 必须被过滤。

### 2.4 结果页

- 继续使用平台统一结果页，呈现有效试次数、正确率、反应时和范式配置中声明的特有效应指标。
- 特有效应指标不根据文件名或数据字段自动猜测，必须由范式包明确选择受支持的结果模板并提供所需字段映射。
- 点探测等范式的指标方向、条件编码和解释由上传者配置，平台负责校验配置所需字段并执行对应的内置计算模板。
- 面向学习者的结果页不显示“尚未配置范式效应指标”等开发状态提示。缺少必要指标配置的范式不能作为合格变更包导出。

### 2.5 管理员页

- 使用独立页面 `admin.html`，不在普通导航、首页和目录页中显示入口。
- 密码校验仅用于防止学生误入，不承诺高强度安全认证。
- 页面不保存或接触 GitHub Token，不直接写入 GitHub 仓库。
- 密码只以摘要形式配置；成功状态仅保留在当前浏览器会话，关闭会话后需要重新验证。

## 3. 范式包协议

首版支持上传 `.zip` 压缩包或选择解压后的文件夹，不支持 RAR 和 7z。

每个范式包包含：

- `manifest.json`：范式 ID、名称、简介、分类、标签、预计时长、版本、作者、入口文件、结果模板和字段映射；
- `description.md`：上传者撰写的范式说明；
- 实验程序：HTML、JavaScript、CSS、图片、音频等运行资源；
- 可选封面图：用于目录卡片和说明页。

范式说明至少覆盖：

- 范式名称与学习目标；
- 实验原理；
- 实验流程与按键说明；
- 记录指标；
- 特有效应指标及其含义；
- 结果理解；
- 教学注意事项；
- 来源或参考文献。

管理员可以上传 Markdown 文件或在管理页粘贴普通文本。粘贴的文本可以转换为 Markdown，并在导出前以网站实际样式预览。

## 4. 管理工作流

1. 管理员通过隐藏地址进入管理页并输入密码。
2. 上传 ZIP 或选择范式文件夹。
3. 浏览器只在本地读取和解析文件，不上传实验材料或试做数据。
4. 管理页依次执行静态校验、运行预览和结果预览。
5. 管理员至少完整试做一次，确认实验可结束并生成统一结果页。
6. 合格范式进入“待添加”或“待替换”清单。
7. 现有范式可以标记为“待删除”，导出前允许撤销。
8. 管理员导出范式库变更包，再由教材编写人员将变更同步到 GitHub 仓库。
9. GitHub Actions 重新生成公开目录并部署 GitHub Pages。

浏览器端管理页不能直接修改已经部署的 GitHub Pages。添加、替换和删除均在变更包同步到仓库并重新部署后生效。

## 5. 校验分层

### 5.1 文件与安全检查

- ZIP 路径穿越、异常文件数量和异常解压体积；
- 必需文件、入口文件和资源引用是否存在；
- 文件名、范式 ID 和目录结构是否合法；
- 是否包含远程数据上传、Pavlovia 服务调用或不允许的外部依赖；
- Markdown 是否包含危险 HTML、脚本或事件属性。

### 5.2 运行兼容性检查

- 实验能否在隔离预览区加载；
- 是否存在明显的脚本错误或资源加载失败；
- 是否按照平台协议产生试次数据；
- 是否发送实验完成事件；
- 是否能把结果交给平台统一结果页。

### 5.3 结果检查

- 正确率字段、反应时字段和有效试次规则是否可用；
- 结果模板所需条件字段是否齐全；
- 特有效应指标能否计算；
- 数据不足、无正确试次和异常反应时是否得到安全处理；
- 说明页对指标方向和含义的描述是否由管理员确认。

每项检查显示“通过、警告或失败”以及具体原因。存在失败项时禁止导出。自动检查只能保证技术兼容性，材料内容与心理学计分规则的科学正确性仍由上传者和管理员负责。

## 6. 变更与删除

- 新范式使用“待添加”状态。
- 相同范式 ID 的新版本使用“待替换”状态，并在导出前显示版本变化。
- 删除使用“待删除”状态，不立即操作文件；管理员可在导出前撤销。
- 变更包包含新增或替换文件，以及一份机器可读的变更清单，列出添加、替换和删除目标。
- 应用变更时只允许操作 `paradigms/packages/` 下经过校验的明确目录，避免误删项目其他内容。

## 7. 错误处理

- ZIP 无法解析、缺失资源或配置错误时保留已上传文件列表和检查结果，便于修复后重试。
- 运行预览崩溃或超时时停止预览，不影响管理页其他候选范式。
- Markdown 渲染失败时显示安全的纯文本回退预览。
- 结果计算失败时显示管理员可读的字段和模板错误，不向普通目录发布半成品范式。
- 导出失败时保留待变更清单，允许重新导出。

## 8. 测试与验收

自动检查覆盖：

- ZIP 和文件夹解析；
- 路径、文件和资源完整性校验；
- Markdown 安全渲染；
- 范式清单的添加、替换、撤销和删除；
- 目录搜索与筛选；
- 结果字段映射和内置结果模板；
- 无有效数据等边界情况。

真实浏览器验收覆盖：

- 首页跳转到独立实验目录页；
- 目录筛选和空结果状态；
- 目录卡片进入说明页；
- 说明页顶部可直接开始实验；
- 实验完成后进入统一结果页并可导出；
- 管理员登录、上传、检查、试做、删除标记和变更包导出；
- 桌面与移动端布局、键盘操作、焦点状态和文本溢出。

## 9. 当前阶段不包含

- 真正的服务器端账号、角色和权限系统；
- 在浏览器中保存 GitHub Token；
- 从管理页直接修改 GitHub 仓库或立即上线；
- 正式科研数据采集、远程数据保存或被试管理；
- 自动判断实验材料和心理学理论是否科学正确；
- RAR、7z 或其他压缩格式支持。

如果未来需要在线直接增删和真实身份认证，应把管理员功能迁移到 CloudBase 等带后端鉴权和存储的环境，而不是继续增强静态密码门槛。
